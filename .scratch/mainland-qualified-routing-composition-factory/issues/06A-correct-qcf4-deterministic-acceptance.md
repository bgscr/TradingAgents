# 06A — Correct QCF4 deterministic acceptance

**Parent specification:** [Mainland qualified routing production composition factory](../spec.md)

**What to build:** Correct only QCF4's over-specified deterministic expectation
so the fresh built-in acceptance path proves truthful statement and indicator
behavior independently. Complete compatible Tushare statements may qualify and
stop statement fallback; complete Tushare indicator values remain retained but
cannot be selected when material filing scope is unproven. Only unresolved
indicator families continue through the plan, lower providers are evaluated on
their own evidence, and every prerequisite and ordinary physical attempt is
counted exactly.

**Blocked by:** 03 — Add static registration and caller precedence; 02D — Add
executable production-source wiring; 04A — Integrate managed eligibility-context
acquisition; 02F — Truthful provider indicator normalization and
compatibility evaluation; 05B — Persist and restore indicator metadata
compatibility.

**Status:** ready-for-agent

## Observable behavior

- QCF4 starts at the statically registered built-in, resource-free blueprint and
  zero-I/O managed composition with no manually seeded context, callable
  runtime, dispatcher selection, or checkpoint.
- For fixed `601328.SS` and `600895.SS` fixtures, the run acquires company-type
  evidence and authoritative BaoStock listing provenance, resolves company type
  once, and single-assigns the immutable Financial Eligibility Acquisition
  Context before ordinary request-factory/dispatcher use.
- Complete compatible Tushare statement artifacts are retained and selected and
  stop lower statement fallback.
- Tushare indicator artifacts/candidates and their 100% value-completeness
  assessments are retained. Ratio/rate/turnover value currency is
  `NOT_APPLICABLE` where `financial-indicator-field-semantics-v1` declares it;
  filing consolidation scope is material and `UNPROVEN`, so affected families
  remain unselected. Missing `f_ann_date` remains current-only at most.
- Only unresolved indicator families continue sequentially through Capability
  Routing Plan 1.2. Each lower provider qualifies only through its own truthful
  metadata; request `CNY`/`CONSOLIDATED` never appears as provider evidence.
- The trace shows exact prerequisite and ordinary physical-attempt cardinality,
  including actual lower-provider work, with no hidden calls, duplicated bulk
  work, provider-specific router branch, retry, fan-out, or selection attempt.
