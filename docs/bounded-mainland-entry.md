# 有界单股票入口

可选的 `-Moneyflow` 和 `-MarginDate` 在保持 Basic 深度下分别启用单股资金流和指定日融资余额辅助观察，默认关闭；
它们不是旧 `flow_sentiment/all` 预设。请求仍占用原 60 次共享预算，范围、来源和限制见
[资金流增强说明](bounded-moneyflow.md)与[融资余额说明](bounded-margin-balance.md)。

以下命令均在已安装、经过绑定核验的项目根目录执行；无需切到候选目录或旧 prepared 包。文件位于工作目录不等于已提交、合并或发布，未提交本身也不阻止本机读取这些文件。当前 Git 状态须独立核实，运行成功不能代替发布审查。

## 从主目录使用

### 回看时复用历史观察

选用融资余额或 PowerShell 资金流时，默认按 `retrospective` 策略读取已完成的请求。命中保留原采集时刻，使用零次发送额度。融资余额仍须匹配本次活动行情快照。旧版东方财富投影缺少完整身份摘要时，需用 `-FundflowObservationSha256` 传入独立核验的原观察摘要（回执中的 `normalized_sha256`）。只采用通过复核的百分比投影。新闻回执没有原始响应，跨会话读取会报告缺失。

`-ObservationCacheMode disabled` 关闭历史观察复用。`-ObservationCacheMode as_known_on_date` 要求这三项观察具有截止日当时可用的证据。现有来源只有回补语义，因此对应读取入口返回缺口且不补采。此参数的范围仅为这三项观察。普通回看模式下，缓存缺失后的提供方访问仍受原会话预算约束。

### 可选东方财富个股资金流（PowerShell）

```powershell
pwsh -NoProfile -File .\scripts\Start-MainlandAnalysis.ps1 -Guided -UseProjectEnv -PowerShellFundFlow
```

在向导中明确选择股票与截止日；例如选择 `601328.SH`、`2026-11-13`。股票没有默认值。
`-PowerShellFundFlow` 默认关闭，与 `-PowerShellNews`、`-Moneyflow`、`-MarginDate` 独立；也可追加到原成对显式股票/日期命令。
Basic 的综合基本面不采集个股资金流。有界入口启用此项时，在原生 Basic 报告落盘后采集辅助观察。使用固定无 profile PowerShell GET、同一请求协调器、60 次共享预算和原绝对期限。
START 前会显示选择和限制；本选项不是新财报、公告、旧 `all` 或完整分析的额外授权。

查询后逐条核验股票/交易所、日期和数值，保留截至日及前 7 个日历日的合格记录，乱序排序、相同重复去重、冲突拒绝，未来记录排除。返回近期列表不证明完整历史或完整交易日覆盖，事后采集不证明截止日当时已公开。
当前只采用官方字段表明确为 `%` 的五类净占比及涨跌幅；金额和收盘价单位倍率尚未独立核实，已从模型、报告和留存投影排除，不换算、不合计。
东方财富主力/订单分类与 Tushare `net_mf_amount` 全单净额是独立口径，不能相加或互换，不填补 AC/FVOCI 等财报缺项、不新增财报指标覆盖或改变投资评级。

有界入口将结果独立归档在同一会话的 `powershell-fundflow.json`，其中 `basic_export_id` 指向已落盘的导出。基础报告保留其发布时的证据和计数，会话结束时的预算记录包含后续辅助采集。这两个阶段顺序执行。若门禁给出非方向性结果或分析未请求该工具，辅助采集跳过。
只保留合格百分比投影、范围、采集时刻和绑定摘要，不保留完整原始响应。普通失败、空窗口和未配置保持不可用；权限、取消、预算、完整性或关闭失败停止。该分支至多一次 GET，不自动重试或分页，也不额外调用模型；完整 Basic 在 START 后仍按原配置调用模型。
合成测试验证正式调度、并发复用和渲染边界；不等同完整 Basic 的新实跑。

字段依据：[AKShare 官方字段表](https://raw.githubusercontent.com/akfamily/akshare/main/docs/data/stock/stock_flow.md)与[官方适配源码](https://raw.githubusercontent.com/akfamily/akshare/main/akshare/stock/flow/stock_fund_em.py)。当前文档名称为 `stock_fund_flow_individual_hist_em`，本机旧适配名称为 `stock_individual_fund_flow`，不能混淆依赖版本。

### 简洁交互入口（本地安装）

```powershell
pwsh -NoProfile -File .\scripts\Start-MainlandAnalysis.ps1 -Guided
```

在普通交互终端选择股票（六位代码及 `.SH`、`.SS` 或 `.SZ`，没有默认股票），填写或确认截止日期，再选择资金流、融资日期与凭据输入方式。简洁模式固定使用 PowerShell 新闻，最多一次 GET；不安装或控制浏览器，不读剪贴板。没有显式 `-Guided` 时原参数与非交互路径不变；也可在 `-Guided` 后提供原有成对 `-Ticker` / `-AnalysisDate` 等参数，已显式启用的选项不会被提示覆盖。`-CheckOnly -Guided` 只检查源码，不弹出向导。

默认日期是上海时区昨日的日历截止，**不是已核验的交易日或完整收盘行情**。生产日历/行情门禁仍决定实际有效交易日；周末、假期或数据尚未发布时不能据此断言数据齐全。融资日期需与最终行情快照的交易日一致，不自动回退；不确定可在融资日期提示输入 `/skip`。日期可以覆盖，仍拒绝未来日期。

向导只读检查固定身份目录内最多 256 个条目，复用同股、未过期且收据/摘要/来源/上市区间通过原校验的身份快照；正式会话会再次绑定并检查有效期。基础注册表已支持的证券不查补充快照。补充路径仅接受可验证的银行身份，不承诺支持所有合法代码。损坏、未来或不可读材料停止，不以刷新掩盖；已有但过期/其他股票的快照不能授权当前股票。

先显示 Basic、增强选项、费用和预算范围，输入 `START` 后建立运行 ID。确需更新时进入原单股身份更新流程，显示精确股票和范围，仍要求 `UPDATE_BANK_IDENTITY:<代码>`。至多一次 Tushare POST，沿用独立 240 秒、原限流、零重试和安全凭据方式；不触发模型，也不重置分析额度。更新失败或取消即停。身份查询归入已建立的这次会话。向导等待、身份准备和后续分析共用从监督进程启动起的 1200 秒；身份更新的实际请求从总额度扣除。分析期限仍可能被身份到期时间缩短。没有金额硬上限，失败请求费用未知不能按零处理。

输入 `/cancel`、Ctrl+C 或 EOF 结束向导；不循环追问或自动重试。无交互终端的 `-Guided` 拒绝运行，自动任务继续使用原显式入口。短输入限制 80 字符，不接受长正文。缺少 PowerShell 时沿既有新闻不可用路径降级，绝不暗中调用 Requests；完整性、权限、取消和预算失败仍停止。向导不启用公告、政策、旧 `all` 或新财报附件。以下旧显式用法继续有效。

### 新闻：PowerShell 自动获取

正式入口通过显式 `-PowerShellNews` 选择此路径，需同时提供 `-Ticker` 和 `-AnalysisDate`。该开关默认关闭；未选时保留原有新闻传输，不扩大其他入口的默认调用范围。
所选路径沿用 Basic 的情绪／新闻工具、来源证据和最终报告，不改变评级规则，也不启用公告、政策或旧 `all`。手工粘贴功能及 `-ManualNews` 参数已移除。

在已安装且源码绑定通过的主目录执行（要求 PowerShell 7.4 或更高的 7.x）：

```powershell
$bankSnapshot = '<现有流程返回且仍有效的 UUID:SHA256>'
pwsh -NoProfile -File .\scripts\Start-MainlandAnalysis.ps1 -Ticker 600919.SH -AnalysisDate 2026-11-13 -BankSnapshot $bankSnapshot -UseProjectEnv -Moneyflow -MarginDate 2026-11-13 -PowerShellNews
```

占位符必须替换；不需要该补充身份路径的已登记股票可省略 `-BankSnapshot`。示例股票／日期可替换，仍须通过原身份、行情、日历和来源门禁。
只有输入 `START` 后才开始收费分析。PowerShell 新闻调用发生在原分析会话内：使用本次启动宿主 `$PSHOME` 中的 `pwsh.exe`，固定脚本以 `-NoProfile -NonInteractive` 调用标准 `Microsoft.PowerShell.Utility\Invoke-WebRequest`。
不读取用户 profile、不继承凭据或代理环境变量，不复制浏览器 Cookie，不伪装 Requests 已恢复；操作系统默认网络配置仍可能影响它，不能据此证明与用户交互 shell 同路线。

每会话最多一次新闻 GET，含失败的尝试计入原 60 次数据／模型预算，SDK／cmdlet 重试和重定向为 0；后续工具调用仅在原股票和已收集的日期窗口内复用投影。
连接／读取各至多 20 秒，父进程还受至多 25 秒和原共享剩余期限约束；取消或期限到达会关闭该次拥有的子进程，不另开进程。
IWR 先在子进程中缓冲响应；最多 1 MiB 才允许传回，匿名 stdout 管道另限 1.5 MB。这不是子进程全部内存或下载量的硬上限。
正文不写临时文件、普通日志或终端。只有通过现有安全、callback、业务状态、集合、股票和日期筛选的文本才能进入证据及模型。普通传输／响应不可用时，报告保留具体类型，不回退 Requests、不打开浏览器、不等待粘贴；预算、取消、权限、源码完整性及资源清理失败仍按原停止规则处理。
显式 `-PowerShellNews` 本身不新增 stdin 交互；`-Guided` 的选择步骤见上节。原入口的 `START`、凭据要求保持不变。PowerShell 新闻响应文本仍受 262144 字符的投影准入上限，超限整体拒绝，不截断成新闻。

新闻筛选窗口为截止日往前 7 个自然日到截止日，上海日期含两端；链接本身是单页搜索，不是供应商历史日期查询。
每条独立筛选，乱序不提前停止，未来条目不进入模型／报告，错误股票／callback 或未知状态不能当成功。新闻分析员提示含本次绑定的精确股票及窗口；超窗请求返回 `powershell_news_query_window_mismatch` 和允许范围，不误称上下文缺失、不补采其他日期。真正无本次绑定时仍返回 `powershell_news_context_missing`；错股或不符的注入身份不能靠替换参数通过。首次、并发和重复的合格工具访问共享同一会话投影与至多一次请求。
`eastmoney_powershell` 表示本次程序选择的 PowerShell 传输。接收时刻不是历史发布时间证明；当前获取历史日文章属于历史回补，单页不保证完整历史覆盖。
原始 JSONP 及其摘要不保存；合格的规范化新闻投影会按既有证据合同进入本地 checkpoint／分析工具材料，报告保留来源和限制，投影摘要不等于原始 HTTP 字节证明。不要将这些真实运行资料提交到公开候选。

PowerShell 生产新闻采用字段投影：额外包络/集合/文章字段仅在有界内存中忽略，不进入日志、证据或摘要；`image`、`extra`、`searchId`、`hitsTotal` 不作准入或覆盖证明。`content`、`mediaName`、文章 `url` 可缺失，缺失描述保持空文本而非编造内容；链接仍按原文章 ID 构造。若提供 URL，仍必须匹配原允许的公开域名及文章 ID，否则拒绝。日期、标题、文章 ID、正确 callback 和目标新闻集合仍必需；带业务状态时必须为已支持的整数 `code=0` 与精确 `msg=OK`，可选 biz 状态若存在必须为空，其他未知或失败业务状态仍拒绝。历史无状态包络保留原 `not_supplied` 语义，不等同供应商成功。

所有文章的核心文本在日期/股票筛选前经过敏感内容检查，未来或错股文章不能掩盖敏感正文。长度上限、重复 JSON 键、非有限数字以及有界嵌套检查保留，文本不执行。旧诊断入口可能留存原文，因此其严格原文留存条件未随生产投影放宽；不要把新投影通过视为原始响应可留存。兼容性修改不代表已确定此前交通银行响应的具体失败字段，也不保证所有公开响应都合格。

来源失败仍为 `article_source_invalid`，安全摘要另提供 `article_source_issue` 固定类别（类型、协议、主机、路径、文章 ID 等），不提供实际 URL、查询参数或字段值。当前规则仍只接受三个既有域名的精确 HTTP 文章链接；HTTPS 单独归类为尚未纳入当前策略，并未据此自动放行。任意一条来源失败仍停止整批，保留首错；此时合格数、日期覆盖和未执行的筛选计数未知，不能把其他条目称为已独立核验。该诊断不追溯恢复此前拒留的响应。

可显式追加 `-NewsSourceIsolation` 选择逐条来源隔离；默认仍是上述严格模式。例如已有基础身份登记的交通银行：

```powershell
pwsh -NoProfile -File .\scripts\Start-MainlandAnalysis.ps1 -Ticker 601328.SH -AnalysisDate 2026-11-13 -UseProjectEnv -PowerShellNews -NewsSourceIsolation -Moneyflow -MarginDate 2026-11-13
```

也可用 `-Guided -NewsSourceIsolation -UseProjectEnv` 交互选择股票和日期。该模式只配合 PowerShell，START 前显示所选策略，仍沿原预算与权限；示例不代表已运行完整分析或缓存已补齐。没有手工粘贴或自动回退其他传输。

逐条模式要求明确通过现有 `code=0/msg=OK` 包络、callback、集合及全页核心文本/容量/深度验证。普通 URL 不匹配或缺失时排除整篇，不保留去掉链接后的正文；只有明确匹配原三个域名、路径和文章 ID 的文章才再做日期和股票筛选。没有扩大来源白名单或访问文章链接。敏感文本、URL中的凭据标记/userinfo、坏核心字段、业务失败或相同文章ID对应冲突内容仍整批拒绝；这些失败的未完成统计保持未知。完全相同的已准入重复条目只保留一条。

收据、准入工具文本与完整报告前部包含原采集窗口的本页记录数、来源排除、格式/日期、窗口外、错股、重复及最终准入数；按顺序互斥计数，来源排除条目不再统计股票/日期。工具子窗口的实际提供数另列。全排除为新闻不可用，完成筛选后的准入0是计算结果，不是“没有新闻”。来源排除时注明部分条目可用，单页历史覆盖始终未知、历史回补限制保留，评分不变。完整报告的统计由本次运行持有的对象显式传入并核对股票/截止日，不从旧JSON恢复权限；离线重渲染若没有该可信对象，不补造统计。

原集成版本通过 75 项有限离线合成用例、两个脚本语法及正式入口源码预检；之后完成一次项目无 profile 子进程真实 GET，HTTP 200，严格准入取得 9 条合格新闻并排除 1 条窗口外条目，响应与子进程正常关闭。该单例证明当次传输及解析成功，不保证其他股票、日期或长期可用，也不是包含此新路径的完整 Basic 实跑。移除手工界面后的源码通过 62 项针对性离线用例、独立复核和正式入口源码预检，没有重复真实请求；历史检查不能自动覆盖新字节。具体运行收据保留本地，不作为公开测试材料。

先在普通账户 PowerShell 做无网络的源码及参数预检：

```powershell
pwsh -NoProfile -File .\scripts\Start-MainlandAnalysis.ps1 -CheckOnly -Ticker 600919.SH -AnalysisDate 2026-11-13 -Moneyflow -MarginDate 2026-11-13
```

`-CheckOnly` 不读取凭据、不导入业务、不验证缓存或身份、不创建会话，也不能证明下一次真实分析成功。它不是完整的运行配置/数据检查。实际入口固定使用主目录 `.venv\Scripts\python.exe`，不是系统 Python；PowerShell、解释器及依赖曾在本机真实运行，不能据此保证环境以后不会变化。

真正运行使用同一入口，替换下面的身份引用，并在范围说明后输入精确的 `START`：

```powershell
$bankSnapshot = '<通过现有流程取得且仍有效的 UUID:SHA256>'
pwsh -NoProfile -File .\scripts\Start-MainlandAnalysis.ps1 -Ticker 600919.SH -AnalysisDate 2026-11-13 -BankSnapshot $bankSnapshot -UseProjectEnv -Moneyflow -MarginDate 2026-11-13
```

占位符不能直接使用；这里不提供凭据。`BankSnapshot` 在语法上可省略，但本地基础身份表已识别的股票才不需要这个补充身份路径；600919 当前依赖其银行身份快照。引用有有效期，不是永久配置；请使用现有身份流程返回的引用及到期信息。实际启动仍检查完整绑定和剩余有效期，身份到期还可能缩短会话期限。股票和日期示例不是对任意证券或当前实时数据就绪的保证。

需要新身份时，现有单股入口如下。**这会发出真实 stock_basic 请求，不是离线预检**；不要仅为例行启动重复更新仍有效的身份：

```powershell
.\.venv\Scripts\python.exe -I -B .\scripts\update_bank_identity.py --refresh-security 600919.SH --use-project-env
```

在交互终端按提示输入 `UPDATE_BANK_IDENTITY:600919.SH`，成功后使用它返回的新引用；失败则停止。该入口只向既定 Tushare HTTPS 接收方发送一次身份查询，不运行模型，也不通过命令参数传 Token。单独执行该命令使用独立授权；通过分析向导执行时，查询占本次 60 次总预算中的一次。不要把该银行补充路径当作任意未知证券的身份认证。

也可以不显式选择股票和日期，进入原菜单：

```powershell
pwsh -NoProfile -File .\scripts\Start-MainlandAnalysis.ps1
```

## 部署绑定与可移植性的边界

当前 `config/bounded_mainland_release.json` 是安装实例的绑定清单，不是通用安装凭证。`scripts/analyze_mainland_bounded.py` 的 `verify_release()` 同时核对：

- `project` 条目：相对路径及已审源码字节的 SHA256，拒绝重复、绝对路径、含 `..` 的路径，以及符号链接／重解析点。
- `python`／`stdlib` 条目：实际解释器环境中指定依赖文件的 SHA256；依赖版本名称相同不等于字节相同。
- `deployment_root`：清单固定根目录与正在验证的源码根目录相符；正式入口另要求该目录自身的 `.venv/Scripts/python.exe`。

这些检查检测相对既有受审清单的漂移；清单自身的可信交付仍是前提，它不是签名认证，也不能用可编辑 JSON 自证可信。测试可显式复用已有解释器来核验候选源码与依赖，但不因此满足候选正式启动条件。

此分离目前是设计边界，尚未实现新的安装器、绑定格式或启动门禁。启用前需确定受审清单的可信交付来源、依赖字节差异的审核方式及本地记录生成／替换权限，并验证拒绝篡改和错误部署根；现有安装检查保持原样。只发布相对模板或删除绝对路径不能使一个新环境直接可运行。

CURRENT 个人研究模式可把经过原始响应、内容摘要、发布记录和最新完整范围核验的 SSE
公共日历用于其他已验证 XSHG／CNY／equity 证券。证券代码后缀本身不是权威身份。
新证明类型为 tushare-sse-exchange-calendar-v2；旧 tushare-sse-current-calendar-v1
证明仍只绑定原证券，不重标旧行情或旧缓存。每只证券的价格键、日期、复权方式和事实来源
仍独立。该证明不提供严格历史 PIT 资格。

SZSE 证券不能消费 SSE 日历，继续依赖现有受信的 generic 日历路径；本次不扩展供应商或
开放其他来源。混合存储中受检查来源损坏、最新版本不完整、缺自然日期或身份不匹配都应
明确停止，不能拼接旧版日期、生成交易日或把非交易日当作缺失行情补造。
已命中的 v2 缓存也须重新核对日历来源。明确的来源／生命周期失败须在新价格请求前终止；

更换源码后，不得仅重写缓存兼容清单中的哈希。必须保留旧清单和失败回执，以当前源码
重做限定的合成缓存矩阵、公开缓存入口及受影响适配器验证，再保存新证据及源码指纹。
离线兼容通过只证明所测机制，不证明某个真实缓存正文、日期覆盖、实时接口或账户权限可用。

## 如何理解来源未知与能力未配置

报告中的“证据缺口与未支持主张”同时列出采集状态和事实缺口。宏观指标、预测市场
只有在来源引用与可信采集记录精确匹配、能力类型不冲突时才显示对应名称；
`not_configured` 表示对应采集记录的能力未配置、未取得可用数据，不代表已采集事实缺少来源。
这个展示说明不启用新供应商，不补造事实，也不提高证据覆盖率或改变评级。
无法绑定的来源仍标为未知。指标的能力名称本身也不能证明供应商直接提供了该指标；
本地派生指标仍需原始行情来源和计算链绑定。

财务调度的规范能力 `company_financials` 同样只在来源引用精确匹配、能力不冲突时
显示“公司财务”。`disconnect` 仍表示该次采集断连、来源不可用；能力名称不是已取得
财务数据或某供应商已核验成功的声明，也不替代审计中的供应商和调用绑定。

“未支持主张”统计状态为 `unsupported` 的主张校验记录，不等于已证伪的错误数量、
缺失数据种类或全文准确率。`numeric_claim_unsupported` 表示所引用证据未通过该主张的
数字支持校验；`details_not_retained` 表示现有保留记录不足以还原具体原因。
未列出的自由正文也不会因未计入该统计而自动获得核验。

新闻“覆盖未知”是另一项限制：当前单页合格条目和上游总命中不能证明历史窗口完整。
显示名称的改进只影响后续生成的报告，历史报告和审计记录不会自动改写。

## 可选财报不完整

统一入口显式启用可选财报缺口准备模式；独立财报脚本默认仍严格要求六个合格视图。
独立脚本的 `--allow-optional-financial-gaps` 必须与精确共享存储绑定一起使用。
仅当前策略声明为可选的财报可以降级。两次工作进程均重新通过真实规范化与评估：
关键字段完整、证券/日期/币种/单位等检查通过，但非关键核心字段覆盖低于90%时，
记录 unavailable，不产生财务制品、canonical fact 或财务投资资格。90%门槛及字段映射不变。
身份冲突、关键字段缺失、错误数字或币种、篡改、缓存失效及必要市场证据不足仍停止。

财报回执保留受限诊断：缺失字段、覆盖率、拒绝类别、原响应哈希、范围及原时间戳。
原始表格值和密钥不会复制进这份诊断。准备成功可能是 passed_degraded；
same_six_outcomes_and_timestamps 表示六项状态一致，旧 same_six_views_and_timestamps
仅在全部合格时为真。父进程只校验受信双进程回执的一致性与来源绑定，
不将自洽JSON当作独立金融认证；分析阶段继续 financial_cache_only，
真实缺口须在报告中披露，不能用其他科目冒充缺失项。

新增财报降级支持的回归必须覆盖原入口的六项比较及独立复用，
不能只验证规范化器，也不能把离线合成流程通过当作真实投资分析已通过。
