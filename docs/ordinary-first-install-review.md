# 普通 Full 首装审查请求与离线安装演练

这项维护工具服务于固定产品提交 `2c3c9470dadf5a2b6d5800b5c2d84c36e18b710c`。请从独立取得并核对过的工具检出运行，候选根目录必须与工具检出分开。工具使用编入自身的该版配方 SHA-256。运行维护工具的 Python、工具来源、固定发行基线与产物来源须由维护者先行审核。开始前，阅读[干净 Windows 首装说明](mainland-clean-start.md)。

## 跨目录交接公开文件

来源端和接收端分别从独立取得并审核过的工具检出运行以下命令。两端都需要受审 Windows Python 3.13。导出端还需要固定产品提交的完整本地 Git 对象和系统安装的 Git for Windows。请将变量设为固定本地卷上的绝对路径，使用普通目录和单链接文件。工具检出、移交包和暂存目标各自独立。暂存及校验期间由操作者独占相关目录。

1. 在来源端导出。工具从固定产品提交读取 Git 对象，按固定配方还原并校验 301 个公开文件。唯一额外文件是列明这些文件的公开索引。运行时、三份本地日期证据、暂存回执和正式清单均由导出器排除。只交接生成的目录，保持相对文件名和字节。

   ```powershell
   py -3.13 -I -S -B .\scripts\handoff_ordinary_full.py export --source-repo "$sourceRepo" --package "$out"
   ```

2. 在接收端从自己的工具检出运行校验。工具从自身固定的配方重新生成预期索引，再逐项校验文件。发送方修改索引不能改变接收端预期。校验成功后预留一个此前不存在的最终目录。

   ```powershell
   py -3.13 -I -S -B .\scripts\handoff_ordinary_full.py verify --package "$received"
   py -3.13 -I -S -B .\scripts\handoff_ordinary_full.py reserve --target "$target"
   ```

3. 在预留目录就地准备有独立来源审核的 `.venv` 和该机有权使用的三份日期证据。运行时审核须覆盖完整运行包；配方仅绑定其中的 24 个 Python 文件和 5 个标准库文件。目标机还须能验证原发行规则规定的证据来源：固定摘要的来源清单、其绑定的原根目录、清单中的唯一条目、来源和目标各自的证据字节。只有在本机已有这些合规输入时才执行下一条。现有政策没有提供向第二台机器分发这些日期证据的授权。不能搬用首台机器的私有材料，也不能使用合成样本补件。

   ```powershell
   py -3.13 -I -S -B .\scripts\handoff_ordinary_full.py stage --package "$received" --target "$target" --evidence-origin "$evidenceOrigin" --pwsh ([Environment]::ProcessPath)
   ```

   默认读取来源根内的已绑定来源清单。若使用既有受审事务前像，可添加 `--source-manifest-backup "$relativePreimage"`。原构建器的相对路径、摘要和来源根规则照常适用。请使用摘要匹配的 PowerShell 7 和与目标 venv 相符的 Python 基础安装。

4. 暂存工具只新建公开文件，在隔离的维护解释器中执行已绑定的正式发行校验函数，最后发布含实际目标路径的暂存回执。中断后如果留下了部分文件，保留现场，在新的预留目录重做；工具不会接管已有目标。生成审查请求的命令见下一节。正式安装还需要独立的首装批准和发布途径。

离线合成回归可用 `py -3.13 -I -S -B .\tests\test_ordinary_full_handoff.py -v` 重跑，覆盖目录搬移、包和独立配方不符、附带旧清单、缺证据、错误运行时及已有目标保护。

## 对已暂存候选生成审查请求

在目标机用与候选 venv 相同的受审 Python 基础安装，进入包含本工具及匹配配方的维护者检出。用已核验的 PowerShell 7 执行，下例中的目标目录须替换成真实的最终候选路径。

```powershell
$target = (Resolve-Path -LiteralPath '..\TradingAgents-candidate').Path
py -3.13 -I -S -B .\scripts\prepare_ordinary_first_install_review.py --candidate $target --pwsh ([Environment]::ProcessPath)
```

该命令仅读候选，不加载其代码。它检查旧正式清单不存在、目标专用暂存回执、配方约束的项目与运行时字节、venv 基础解释器设置和 PowerShell 文件摘要。成功时只向标准输出写入未批准的 JSON。审查请求含产品提交、配方摘要、目标目录及其文件身份的绑定、Windows 安装标识的绑定、拟发布清单的精确字节摘要和文件数。将请求作为本机维护材料处理；主机和目录绑定即使经过哈希仍可能关联到该安装。报告中不含账户配置、行情、机器标识原值或可供正式入口读取的清单。

传统原地构建的候选沿用 `build_ordinary_full.py --verify` 独立复验。跨目录移交的审查请求按上一节先做接收端 `verify` 和 `stage`，再由本工具独立复读目标字节和路径绑定。若正式签发要求旧构建器的完整 `--verify` 回执，该步骤仍需一个同时具备冻结 Git 对象和合法原根证据的来源目录；缺件时停在待审状态。三份日期证据仍须经过来源、用途与摘要审核。运行时清单与 PowerShell 摘要只覆盖指定文件，完整运行包及其来源另需审核。

审查请求只描述一次静止窗口下的测量；目录或文件有并发修改时应重新取证。来自候选的回执、请求或摘要自身均不能批准发布。实际发行批准还需维护者从目标候选之外取得的权威输入，绑定本次精确版本、主机、目标、字节和发行用途。发布时需重新核验上述绑定，并以不可覆盖方式提交正式清单。公开主线已知的过渡工具仅适用于其硬编码的既有安装、版本和新旧摘要。此命令没有生产批准输入、签发、安装或恢复参数。

## 实际运行独立批准的合成安装

从同一源代码检出，在 Windows 上执行：

```powershell
py -3.13 -I -S -B .\tests\ordinary_first_install_fixture.py
py -3.13 -I -S -B .\tests\test_ordinary_first_install_review.py -v
```

第一条在全新临时目录暂存一份固定、不可执行的示例文件。单独的测试审核方从自己的版本、预期内容、指定的模拟主机和目标目录构造本次训练批准。模拟验证方通过候选以外的测试通道收到批准摘要，再核对批准原文、实测字节及绑定。全部匹配才用同盘 Windows 重命名，将示例文件和训练回执一起发布到空缺的示例安装目录。命令核对安装内容后清理自己的临时目录。批准摘要的独立传递仅由测试夹具模拟；它不是生产签名服务。两条命令均不加载供应商配置，不启动正式入口，也不会生成正式清单。

第二条回归涵盖无批准、候选自述、替换批准、内容篡改、错主机/版本/目录、重复安装、已有内容保护和原子发布失败。合成配方只能通过单测进程内的测试输入走请求正例，公开审查命令对该配方返回拒绝。

## 第二台机器实测

在两台独立机器上分别从目标最终目录采集脱敏回执，来自机器 A 的批准不能用于 B。在取得可合法使用的发行输入及真实独立批准渠道后，维护者须用该机的正式发布机制完成第一次签发，再用公开 PowerShell 入口执行 `-Full -Ticker 600895.SH -CheckOnly` 并核对退出码、安装完整性及本机行情证据。测试演练的成功不授予该操作的权限。
